Solution. If theme behavior grows, give document theme one owner across load, navigation and toggling; keep the control focused on user intent.

Depth / deletion test. Deleting today’s toggle behavior would remove real persistence and restoration, not just indirection. Extracting it unchanged would merely move complexity: insufficient depth on its own.

Why not now. Most implementation already has locality in 22 lines of toggle script. No observed runtime failure or second theme consumer justifies a new module today.

  • Potential locality: document state ownership
  • Potential leverage: load and navigation
  • Depth must exceed mere relocation

Adapter discipline. Only browser storage is present as a persistence adapter. A swappable storage seam would be hypothetical; keep native browser behavior rather than invent another adapter.

The interface is the test surface. Verify saved dark theme on full load, repeated client navigation, then toggling: visible palette, icon and saved choice must agree. Browser interaction should exercise the interface, not private event helpers. Not executed during this review.
